# 넥스트레벨 유소년 농구캠프 — 측정 데이터 웹

캠프마다 쌓이는 바이오메카닉스 측정 데이터를 한곳에서 봅니다.

1. **대시보드** (`/`) — 누적 데이터로 만든 나이대·성별 기준값을 그래프로: 참가자 구성, 지표 17개 분포 한눈에 보기, 선택 지표 상세(분포·선수별 위치·캠프별 추이), 남녀 평균 비교, 상세 수치 표
2. **개인 리포트** (`/r/열람코드`) — 같은 성별·나이대 기준 백분위로 강·약점 진단, 2회 이상 참가자는 변화 추적, PDF 저장
3. **관리자** (`/admin`) — 엑셀 업로드 → 캠프 선택/생성 → 미리보기 → 저장, 선수 병합·수정, 캠프 관리, 측정오류 기준표

기술 스택: Next.js 16 (App Router) · TypeScript · Tailwind CSS 4 · Recharts · SheetJS · Supabase(Postgres) · Vercel

## 1. 실행 방법

```bash
npm install

# 1회차 엑셀을 data/private/ 에 둔다 (개인정보라 git에 올리지 않음 — .gitignore 처리됨)
cp "측정 데이터.xlsx" data/private/camp-2026-02.xlsx

npm run seed        # → data/db.json 생성 (1회차 캠프: 남 28명, 여 29명)
npm run dev         # http://localhost:3000
```

- 관리자 로그인: 개발 모드에서 환경변수가 없으면 비밀번호 `admin`. 운영에서는 `ADMIN_PASSWORD`, `SESSION_SECRET` 필수 (`.env.example` 참고).
- 선수별 열람 코드는 **관리자 → 선수 관리**에서 확인합니다.

### 변화 추적 화면 미리 보기 (가상 2회차)

실제 데이터는 1회분뿐이라, 변화 추적 화면을 보려면 가상 2회차가 들어간 **별도 파일**을 만듭니다. 실제 `data/db.json`은 건드리지 않습니다.

```bash
npm run seed:demo                          # data/db.json → data/demo.db.json 복사 + "2026년 8월 캠프 (데모)" 24명 추가
DATA_FILE=data/demo.db.json npm run dev
```

### 검사

```bash

npm run typecheck
npm run lint
```

`tests/seed-validation.test.ts`가 요구사항의 검증 기준을 확인합니다.

## 2. 운영 배포 (Supabase + Vercel)

1. Supabase 프로젝트를 만들고 **SQL Editor**에서 `supabase/schema.sql` 실행
   (테이블 4개 + 기본 측정오류 기준표 + RLS 활성화. 공개 정책이 없어 브라우저에서 직접 읽을 수 없음)
2. 로컬 `.env.local`에 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` 입력 후 `npm run seed` → 1회차가 Supabase에 들어감
3. Vercel에 저장소 연결, 환경변수 4개(`ADMIN_PASSWORD`, `SESSION_SECRET`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`) 설정 후 배포

> Vercel은 파일 시스템이 읽기 전용이라 로컬 파일 저장소를 쓸 수 없습니다. 운영에서는 반드시 Supabase를 설정하세요.
> 서비스 롤 키는 서버에서만 씁니다. `NEXT_PUBLIC_` 접두사를 붙이지 마세요.

## 3. 새 캠프 데이터 추가 절차

**관리자 화면 (권장)**

1. `/admin/import` → 엑셀 파일 선택. 파일은 브라우저에서 읽고, 저장을 눌러야 서버에 기록됩니다.
2. 가져올 시트 확인 — 이름이 `원자료`로 시작하는 시트가 기본 선택됩니다.
   - 한 행 = 선수 1명, 첫 열 = `이름`, 나머지는 26개 지표 헤더 (예: `점프 높이 (cm)`)
   - 성별: 시트 이름에 `남`/`여`를 넣거나 `성별` 열 추가
   - 선택 열: `생년`(또는 `출생연도`·`생년월일`), `학년`(예: 초6, 중1), `소속팀`
3. 캠프 선택 또는 새로 만들기 (이름·날짜·장소). **캠프 날짜로 측정 당시 나이를 계산**합니다.
4. 미리보기
   - 측정오류 기준표에 걸린 값은 빨간 칸으로 표시 (저장은 되지만 통계에서 제외)
   - **동일인 후보**: 이름·성별·생년이 같은 기존 선수가 있으면(생년이 한쪽이라도 비어 있으면 이름·성별만으로) 확인을 요청합니다. "기존 선수에 연결"하면 같은 `player_id`로 이어져 변화 추적에 들어가고, "신규 등록"하면 새 선수가 됩니다. 일괄 버튼으로 한 번에 처리할 수도 있습니다.
   - 모든 후보를 결정해야 저장 버튼이 켜집니다.
5. 저장 → 신규 선수에게 열람 코드가 자동 발급됩니다. **선수 관리**에서 코드를 확인해 선수·보호자에게 전달하세요.

**명령줄 (대량·초기 적재)**

```bash
npm run seed -- data/private/camp-2026-08.xlsx --name "2026년 8월 캠프" --date 2026-08-10 --location 서울
```
동일인 후보가 1명이면 자동 연결, 2명 이상이면 건너뛰고 알립니다 (그 행은 관리자 화면에서 처리).

**업로드 후 할 일**

- 선수 관리에서 생년·학년·소속팀 입력 → 나이대 기준이 계산됩니다. 현재 1회차 엑셀에는 나이 정보가 없어 전원 "나이 미입력"입니다.
- 잘못 나뉜 동일인은 선수 상세 → **선수 병합**으로 합칩니다 (같은 캠프 기록이 겹치면 남기는 쪽 기록 유지).

## 4. 백분위 계산 방식

### 공식

엑셀 `PERCENTRANK.INC`와 같은 방식입니다.

```
백분위 = (기준 집단에서 나보다 기록이 나쁜 선수 수) ÷ (기준 집단 인원 n − 1) × 100   → 반올림해 0~100점
```

- 기준 집단에는 본인도 포함됩니다. 가장 좋은 기록 = 100점, 가장 나쁜 기록 = 0점.
- 동점자는 "나쁜 기록"으로 세지 않으므로 같은 점수를 받습니다.
- **예시** — 김OO(남, 점프 44cm)의 힘생성비율 1,098N/s: 남자부 28명 중 이보다 낮은 선수 1명 → 1 ÷ 27 × 100 = 3.7 → **4점**.
  방향전환 손실 17.7%(좌 17.6, 우 17.8 평균): 이보다 손실이 큰 선수 18명 → 18 ÷ 27 × 100 = 66.7 → **67점**.

### 지표 방향

| 구분 | 지표 | 처리 |
|---|---|---|
| 높을수록 좋음 | 점프 높이, 최대 지면반력, 충격량, 힘생성비율, 엉덩이 기여도 | 나보다 **낮은** 값의 수 |
| 낮을수록 좋음 | 10m 구간, 505 전체 기록, 방향전환 구간, 방향전환 손실, 예비·마지막스텝 시간 | 나보다 **높은(느린)** 값의 수 → 반전 |
| 방향 없음 | 신장, 체중, 무릎 기여도, 외반슬/내반슬, 예비·마지막스텝 감속기여 | 백분위 없이 **기준 대비 위치**: 표준점수 z = (값 − 기준 평균) ÷ 표준편차. \|z\| < 0.5 "평균 수준", 0.5~1.5 "높은 편/낮은 편", 1.5 이상 "매우 높음/매우 낮음" |

- 무릎 기여도는 요구사항 목록에 없어 방향 없음으로 두었습니다 (엉덩이 기여도와 합이 100%인 보완 지표).
- **좌우를 따로 잰 지표**는 양측 평균을 씁니다. 한쪽이 결측·측정오류면 남은 쪽 값을 쓰고, 좌우 차이(좌 − 우)는 리포트의 "좌우 비교"에 따로 표시합니다.

### 기준 집단

- **같은 성별 + 같은 나이대**, 전체 캠프 누적 데이터. 한 선수가 여러 캠프에 참가하면 각 측정이 따로 들어갑니다.
- 나이 미입력이거나 해당 나이대 인원이 10명 미만이면 **같은 성별 전체**로 대체하고 리포트에 그 이유를 표시합니다. 리포트 상단 토글로 "성별 전체" 기준을 직접 고를 수도 있습니다.
- 나이대: 10세 이하 / 11–12세 / 13–14세 / 15–16세 / 17세 이상 / 나이 미입력
- 측정 당시 나이 = 캠프 연도 − 생년 (그해 도달하는 만 나이). 생년이 없으면 학년 환산(초n → 6+n세, 중n → 12+n세, 고n → 15+n세).

### 강점·약점 판정

- **핵심 지표 8개**(점프 높이, 최대 지면반력, 충격량, 힘생성비율, 엉덩이 기여도, 10m 구간, 505 전체 기록, 방향전환 손실) 중 백분위가 가장 높은 지표 = 강점, 가장 낮은 지표 = 약점. 동점이면 지표 목록 순서상 앞의 것.
- **세부 지표**(방향전환 구간, 예비·마지막스텝 시간)는 백분위 막대를 따로 보여주되 강·약점 후보에서는 뺍니다.
  - 방향전환 구간은 505 기록·방향전환 손실과 겹치는 하위 구간이고, 스텝 시간은 기술 세부 지표입니다.
  - 이 구분이 있어야 요구사항의 검증 예시(방향전환 손실 67점 = 강점)가 성립합니다. 스텝 시간까지 후보에 넣으면 같은 선수의 마지막스텝 시간(0.30초, 89점)이 강점이 됩니다.
  - 바꾸려면 `src/lib/metrics.ts`의 `core` 값을 수정하세요.

### 측정오류 기준표

물리적으로 불가능한 값은 자동 표시되어 **통계·백분위에서 빠지고 관리자 화면에만** 보입니다. 원래 값은 지우지 않으므로 기준을 바꾸면 즉시 다시 계산됩니다 (`/admin/rules`).

| 기본 기준 | 1회차 해당 |
|---|---|
| 최대 지면반력 < 300N | 2건 |
| 예비스텝 시간 > 0.5s (좌·우) | 1건 |
| 마지막스텝 시간 > 0.8s (좌·우) | 6건 |

통계: 표준편차는 표본 표준편차(n−1, 엑셀 STDEV.S). n이 10 미만인 그룹에는 "표본 부족"을 표시합니다.

## 8. 알려진 제한

- Supabase 어댑터(`src/lib/store/supabase.ts`)는 실제 Supabase 프로젝트에 연결해 시험하지 못했습니다. 로컬 파일 저장소로는 업로드·병합·수정·삭제 전 과정을 확인했습니다.
- `xlsx`는 npm 최신판(0.18.5)을 씁니다. SheetJS 최신판은 npm이 아닌 `https://cdn.sheetjs.com`에서 배포되므로 운영 전 `npm i https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`로 바꾸기를 권장합니다. 엑셀 파싱은 관리자 브라우저에서만 일어납니다.
- PDF는 브라우저 인쇄(“PDF로 저장”)를 씁니다. A4 인쇄용 스타일이 적용됩니다.
